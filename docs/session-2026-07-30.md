## Déroulé

1. **Diagnostic honnête** — après revue du code (`vinDecoder.ts`, `DecodeurVinWindow.tsx`, câblage
   menu/bouton/signal cross-fenêtre) : **la logique n'était pas cassée**. Le décodeur décodait bien,
   mais rendait un **résultat inutile**. Deux erreurs de conception :
   - **« ✗ Chiffre de contrôle incorrect » était trompeur** — ce chiffre (position 9) n'est
     obligatoire **qu'en Amérique du Nord** (WMI commençant par 1-5). Les véhicules de transit
     (Europe, Japon, Asie) ne l'ont quasiment jamais valide : c'est **normal**, pas une erreur.
     On affichait donc un gros ✗ rouge bloquant sur un VIN parfaitement sain.
   - **Table WMI trop courte** — `SB1` (Toyota, usine UK), le VIN de test de l'utilisateur, en était
     absent → « Constructeur Inconnu ».
2. **Demande de l'utilisateur**, reprise telle quelle comme cahier des charges :
   > *« Élargir la table WMI autant que possible car je veux que le decodage soit efficasse ! et si la
   > limite du decodage local est vraiment atein alors tu peux ajouter un mecanisme automatique de
   > decodage en ligne […] : si decodage local ne trouve pas le resultat alors verifier si la pc est
   > connecter : si oui alors se connecter a l'[API] en ligne decoder et afficher le resultat ! »*
3. **Cartographie avant plan** → découverte structurante : la **CSP** de l'app principale est
   restrictive (`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'`, **pas de
   `connect-src`**) → le renderer **ne peut pas** appeler une API externe. **Le fetch NHTSA doit donc
   se faire dans le processus main.** C'est cette contrainte qui a dicté l'architecture.
4. **Plan détaillé écrit** : `docs/superpowers/plans/2026-07-30-decodeur-vin-en-ligne.md` — 4 phases TDD.
5. **Exécution par sous-agents**, phase par phase, avec relecture entre chaque.
6. **Validation E2E dans l'app réelle**, puis push.
7. En fin de session, nouvelle demande : **rendre le décodeur vivant et animé** (démarrée, coupée).

## Ce qui est fait

### Phase 1 — Local (`2bb9078`)
- **Validation reformulée** : `structureValide` (17 caractères, charset VIN, pas de I/O/Q) devient le
  seul critère bloquant. Le chiffre de contrôle passe en **note secondaire** avec 3 états :
  *conforme* / *incorrect — VIN nord-américain suspect* / **non applicable (VIN hors Amérique du Nord)**.
  Champs dédiés : `chiffreControleRequis` (`/^[1-5]/`), `chiffreControleOk`, `noteControle`.
- **Table WMI portée à 79 entrées**, ciblées sur le parc transit ouest-africain : `SB1` (Toyota usine
  UK), usines Toyota (`JT*`, `VNK`, `NMT`, `MR0`, `AHT`), Mercedes, VW, PSA, Renault, Hyundai, Kia,
  Nissan, Honda, Ford, BMW, Fiat, Isuzu, Mitsubishi, Suzuki, Mazda, Subaru, Hino, et les poids-lourds
  MAN / DAF / Scania / Volvo / Iveco / Renault Trucks (catégorie **Camion**, confiance **élevée**).
- Champ `valide` conservé en **alias déprécié** de `structureValide` le temps de la Phase 3, pour ne
  pas casser le typecheck de `DecodeurVinWindow.tsx`. **8 tests verts.**

### Phase 2 — En ligne, côté main (`ddba439`)
- **`src/main/vinOnline.ts`** : `decoderVinEnLigne(vin)` → API **NHTSA vPIC** (gratuite, sans clé)
  `https://vpic.nhtsa.dot.gov/api/vehicles/DecodeVin/{vin}?format=json`, `AbortController` **6 s**,
  `ok = (Make || Manufacturer) && ErrorCode !== '11'`.
- **`mapNhtsaCategorie(vehicleType, bodyClass)`** : TRUCK/PICKUP/TRACTOR/CAB → **Camion** ;
  BUS/MOTORCYCLE/TRAILER/VAN → **Autre** ; PASSENGER/MPV/SUV/SEDAN/HATCHBACK/WAGON/COUPE → **Voiture**.
- Câblage : IPC `vin:decodeOnline` dans `main/index.ts`, `vinDecodeOnline` au preload,
  `electronApi.vinDecodeOnline` + interface `VinEnLigne` (avec repli typé si `window.api` absent).
  **6 tests verts.**

### Phase 3 — UI (`7d9cc5f`)
- `DecodeurVinWindow.tsx` réécrit : décodage local → **secours en ligne automatique** si
  (catégorie nulle ou constructeur inconnu) **et** `navigator.onLine` ; **cache** `localStorage`

## Pièges et détails techniques à retenir

- 🔴 **La CSP interdit tout appel externe depuis le renderer** → tout décodage en ligne passe
  obligatoirement par le processus **main** + IPC.
- 🔴 **`npm run typecheck` n'existe pas** dans STCA-Electron. Utiliser :
  `npx tsc --noEmit -p tsconfig.node.json && npx tsc --noEmit -p tsconfig.web.json`.
- ⚠️ **5 tests en échec** (`MainScreen.test.tsx`, `MenuBar.test.tsx`, AntD/jsdom) sont
  **pré-existants** — vérifié par `git stash`. Sans lien avec ces changements.
- Le chiffre de contrôle se calcule par translittération × poids
  `[8,7,6,5,4,3,2,10,0,9,8,7,6,5,4,3,2]`, somme, modulo 11 (10 → `X`).
- Les processus Electron résiduels et le verrou d'instance unique ont gêné plusieurs fois :
  `taskkill //F //IM electron.exe`.
