## Partie 2 — L'efficacité : le cahier des charges de l'utilisateur

> *« qu'est ce qui fait un bon decodeur VIN ? c'est lorsque celui ci arrive a me donner au moins
> **60 % minimum** des decodages les informations suivantes : **la marque, le modele, l'année**
> minimum, et bien sûr plus… sans ca le decodeur n'est pas efficasse ! c'est un projet qui me tient a
> coeur car **j'ai un autre gros projet basé sur le VIN decoding à venir**. »*

### Deux apports décisifs de l'utilisateur

1. **Un corpus réel** : `F:\AI PROJECTS\Table correspondanceVIN` — **100 533 lignes**
   (VIN → marque, modèle, année), dont **98 821 VIN valides**.
2. **Sa connaissance métier sur les années**, qui a directement dicté l'algorithme :
   > *« seul les vehicules de la base amerique et canada respectent la position 10 pour l'année.
   > les autres pas beaucoup »*
3. Une piste complémentaire : les décodeurs en ligne **par marque**, ex.
   `https://www.toyodiy.com/parts/q?vin=…` pour Toyota — retenue pour le bouton « Fiche constructeur ».

### La recette conçue

- **Signature de VIN** : `sig8` = positions 1-8, avec **repli `sig6`** = positions 1-6.
  L'index associe une signature → marque/modèle les plus fréquents + histogramme d'années.
- **Règle d'année** (issue de l'apport de l'utilisateur) : si **WMI nord-américain** (1-5) →
  **position 10** ; sinon → **médiane pondérée de l'historique de la signature**, sauf si la position
  10 tombe dans la plage de l'historique (elle est alors retenue). Champ `anneeSource` :
  `position10` / `signature` / `aucune`.
- **Nettoyage des libellés** du corpus : `"TOYOTA - AVENSIS KOMBI 03-06 >> AVENSIS '03"` → marque
  `TOYOTA`, modèle `AVENSIS`.

## Pièges rencontrés

- 🔴 **`vite-node` échoue sur ce poste** (`ERR_MODULE_NOT_FOUND`) : l'**espace dans le chemin**
  `F:\AI PROJECTS\…` casse la résolution d'URL de Vite pour un import hors du dossier du script.
  → **Utiliser `npx tsx scripts/vin-benchmark.mjs`** (esbuild, sans serveur de dev).
- `skipDuplicates: true` **non supporté** par le connecteur SQLite de Prisma 6.19.3 → retiré ; l'unicité
  est garantie par le drapeau `Parametre.vinSeedImported` et par la déduplication à la génération.
- **4 processus `electron.exe`** tenaient un verrou Windows (EPERM) sur le moteur Prisma avant
  `prisma generate` → à tuer avant.
- Le CSV contient **909 libellés avec virgules/guillemets** → parsing par le module `csv` de Python,
  pas un `split(',')` fragile.
- `echantillon.csv` est **gitignored** — les données brutes ne sont pas dans le dépôt.
