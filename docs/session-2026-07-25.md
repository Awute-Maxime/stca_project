# Session du 25 juillet 2026 — Phase 3 : bascule des référentiels vers la base

Démarrage de la Phase 3 (localStorage → base de données SQLite). **Quatre
domaines migrés** en une session, avec mise en place du modèle asynchrone
réutilisable. L'app reste fonctionnelle à chaque étape (bascule domaine par
domaine, testée et validée).

## Le modèle asynchrone (socle réutilisable)
- `src/main/referentiels.ts` : chaque domaine expose `list` (lecture) +
  écritures ; après chaque écriture → **`diffuserChangement(domaine)`** qui
  envoie `db:changed` à TOUTES les fenêtres (remplace l'événement `storage` du
  localStorage pour la synchro MDI).
- `preload` + `@api/electron` : IPC typés + `onDbChanged`.
- Côté renderer : chaque store garde la **même API** (les consommateurs ne
  changent pas). Deux variantes de cache :
  - hook seul (types de véhicule, marques) ;
  - **cache module** (destinations, assurances) pour garder des getters
    synchrones utilisés hors composants (recherches par code, dropdowns,
    Facture/Feuillet 3).

## Domaines migrés (commits)
1. **Types de véhicule** (23e1a3d) — table `categorie_vehicule` (← CATVEH).
   Pose le socle + `db:changed`.

   `assurancesStore`.

## Deux bugs trouvés et corrigés (domaine assurances)
- **Condition de course à l'amorçage** : plusieurs fenêtres appelaient les
  `*List` en parallèle sur base vide → chacune amorçait → assureurs dupliqués
  (POOL TPV en triple ; pas de contrainte d'unicité sur `nom`). → **amorçage
  unique et sérialisé** : `amorcerReferentiels()` (un verrou `amorcagePromise`
  partagé) amorce catégories/destinations/marques/assurances une seule fois par
  process ; les `*List` l'appellent au lieu d'amorcer elles-mêmes.
- **Détail des primes incohérent dans seed.mjs** : ancien détail (somme 12 000)
  codé en dur avec le nouveau tarif 13 000. → le seed **dérive** désormais le
  détail du tarif (somme = tarif exactement : 13000/19500/13000).
