### 🔴 Les pièges rencontrés — à ne pas réapprendre

1. **Prisma / electron-builder** : `node_modules/.prisma` n'est **jamais** inclus dans l'asar (dossier
   masqué, filtré même via `files`). Le copier à côté ne suffit pas non plus, la résolution partant de
   l'asar → « Cannot find module '.prisma/client/default' ».
   **Solution retenue : `"asar": false` + extraResources `node_modules/.prisma/client` →
   `app/node_modules/.prisma/client`.** C'est le commit *« l'app installée démarre enfin »*.
2. **`ELECTRON_RUN_AS_NODE=1` est présent dans l'environnement de la session** → tout `.exe` Electron
   lancé depuis là démarre en mode Node et sort aussitôt. Toujours
   `Remove-Item Env:ELECTRON_RUN_AS_NODE` avant de tester un build.
3. **NSIS `/D=` ne supporte pas les espaces** en installation silencieuse (« F:\AI PROJECTS\… » est
   coupé et devient `F:\AI`). Contournement : créer une **jonction** sans espace
   (`mklink /J F:\TCITJ "<cible>"`), installer par elle, puis la retirer.
   ⚠️ **Sans importance pour l'utilisateur final** : l'installeur graphique gère très bien les espaces.
4. Windows affichera **SmartScreen** (application non signée) — documenté dans la notice.
5. Le dossier `userData` s'appelle **`tcit-desktop`** (le `name`), pas `TCIT`.
